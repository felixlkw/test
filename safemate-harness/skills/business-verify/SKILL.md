# 기업 정보 검증 절차

## 왜 필요한가

호반·대한전선처럼 M&A·자회사 구조가 빈번히 변하는 그룹은 1년 전 정보도 stale 위험. 카탈로그·분석 보고서에 자회사명·사업 영역을 인용하기 전에 **반드시 web search 검증**.

## 검증 트리거

다음 정보를 출력하기 전 검증:
- 자회사·계열사 이름
- 인수합병·매각 사실
- 공장·사이트 위치
- 시공능력평가 순위
- 대표 프로젝트·수주 실적
- 매출·임직원 수 같은 수치

## 검증 방법

### 1. Primary 출처 우선
- **공식 IR 자료** — 회사 홈페이지의 사업보고서·연차보고서
- **금융감독원 DART** (https://dart.fss.or.kr) — 상장사 공시
- **언론 기사** — 인수합병 발표 기준

### 2. Secondary 출처 (보조)
- 위키피디아 (영문 우선, 한국어는 보완)
- 산업 데이터베이스 (시공능력평가는 국토교통부 공시)

### 3. 검증 안 되면 표시
- "<자회사명> (검증 필요)" 명시
- 또는 해당 항목 자체 삭제

## 검증 쿼리 패턴

```
WebSearch:
- "<회사명> 자회사 2026"
- "<회사명> 계열사 현재"
- "<회사명> 인수" (최근 인수 확인)
- "<회사명> 매각" (최근 매각 확인)
- "<회사명> 사업영역"
```

영문도 함께:
- "<English Name> subsidiaries"
- "<English Name> acquisition"

## 흔한 실수

- 위키피디아 한국어 페이지만 보고 인용 — 업데이트 늦을 수 있음.
- 영문명·한글명 혼동 — 대한전선 = Taihan Cable & Solution, 호반 = Hoban (영문 표기 헷갈리기 쉬움).
- "등(等)" 으로 얼버무리기 — 명시적 검증 또는 제거.
- 출처 명시 안 함 — 신뢰성 떨어짐, critic 이 P0 지적.

## 시간 의존성 메모

```
검증 일자: YYYY-MM-DD
출처: <URL 또는 보고서명>
```

분석 보고서나 카탈로그 note 필드에 명시. 6개월 이상 경과 시 재검증.

## 출력

- 검증된 항목 + 출처 URL + 검증 일자.
- 검증 실패 항목 + 사유 (출처 부재·정보 불일치).
- "검증 필요" 표시된 항목 리스트.
